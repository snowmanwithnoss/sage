# Auth plan (Better Auth)

Status: shipped 2026-10-20 (https://herbs.aroundme.workers.dev).

## Decisions

- **Sign-in:** email + password via Better Auth. No email verification, no password reset (no email service yet).
- **Gating:** browsing is public; posting requires login; users can edit/delete only their own spots.
- **Existing spots:** wiped (test data).
- **Attribution:** owner stored but never exposed. API returns `is_mine: boolean` per spot instead of `user_id`.

## Steps

0. **Pay down debt first:** extract shared `Spot` type + danger constants (min/max/default) into one module imported by both `src/` and `web/`.
1. **Migrations:** replace `schema.sql` with `migrations/` (`wrangler d1 migrations`):
   - `0001` baseline `spots`
   - `0002` Better Auth tables (`user`, `session`, `account`, `verification`, plus rate-limit table), generated by the Better Auth CLI
   - `0003` drop + recreate `spots` with `user_id TEXT NOT NULL REFERENCES user(id)`, index on `user_id`, and the `danger` CHECK constraint
2. **Worker:**
   - `createAuth(env)` per request (bindings are per-request); mount at `/api/auth/*`
   - session middleware puts `user | null` on the Hono context; `requireUser` guard
   - `GET /api/spots` public, adds `is_mine`
   - `POST /api/spots` requires auth
   - `PATCH /api/spots/:id` / `DELETE /api/spots/:id` scoped `WHERE id = ? AND user_id = ?` (404 if not owner)
   - `BETTER_AUTH_SECRET` as a wrangler secret (`.dev.vars` locally, gitignored); `BETTER_AUTH_URL` var
   - Better Auth rate limiting on, `storage: "database"` (Worker isolates don't share memory)
3. **Frontend:**
   - `better-auth/react` client (same package)
   - sign in / sign up dialog; account button overlay on the map
   - clicking the map while logged out prompts sign-in
   - popup shows Edit / Delete on own spots; Edit reuses the add form
   - verify cookies work through the Vite `/api` proxy in dev
4. **Review:** security review of the branch before merge.
5. **Deploy (needs explicit OK):** set secret, apply remote migrations (**deletes live spots**), deploy.

## Accepted gaps (to tech debt)

- No password reset — forgotten password = lost account
- No email verification — anyone can register any address
- Better Auth rate limit only covers `/api/auth/*`; `POST/PATCH/DELETE /api/spots` still need their own per-user limit
